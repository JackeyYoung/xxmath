## 一、架构铁律(六条,违反任何一条即返工)

1. **拒绝全量重绘**
   禁止用 innerHTML 重新渲染交互舞台。两种已验证的落地形态:
   - **不可变行**(m1):算式行一旦生成就不可变,新步骤只"追加"新行;
     被合并的格子用同尺寸静态文本回填原槽位,槽位永不移动。
   - **建格一次 + 注册表**(m9):网格按题目构建一次,所有格子进注册表
     (`data-m9key`),之后只做"原地文字/档位更新"。
   唯一允许整体清空的时机:**换新题**。

2. **布局锁死(Layout Shift 零容忍)**
   所有格子固定宽高(来自 tokens),数字 1 位变 3 位排版不位移;
   CSS Grid 轨道固定。**严禁用 transform 把上排元素挪到下排伪造动画**
   (会崩塌整个网格)——需要"掉落"效果时,在目标位置直接渲染新元素,
   对它自身做 y:-20 → 0 的 back.out 动画,源位置原地变灰占位。

3. **纯函数分离**
   数学推导全部放 `grades/grade3/scoring/mX.js`(可测试、零 DOM)。
   渲染层禁止重新推导数学——**同一份数学只允许一份实现**,
   渲染层需要什么推导,就在 scoring 里导出纯函数(如 divisionSteps),
   并用测试锁定"两处实现必须一致"。

4. **状态驱动动画**
   先算后动:GSAP `onComplete` 里才提交状态/交还档位控制权。
   动画中的元素打 `dataset.b1Animating = '1'` 标志,
   档位刷新器(`setTier`/`setCellText`)见到标志必须跳过,
   动画 onComplete 清标志并触发一次刷新。

5. **单一判定入口**
   "当前等待用户填什么"只允许一个函数回答(m1 无此需求;m9 是
   `currentTarget()`:由 waitingFor + step 推出 {key, cellKey, maxlength}),
   判卷、挂答案槽、键盘缓冲上限、滚焦 **全部** 从它取值。
   入口第一行:`if (!waitingFor) return null`(防完成态残留输入)。

6. **不可变行的陈旧监听必须退役**
   行/网格提交后,旧行剩余的可点元素立即锁定
   (class 换掉 + `row.dataset.committed='1'`,点击入口二次校验),
   否则旧索引的监听器会静默吞掉点击(踩过)。

## 二、五档色彩生命周期(双色板)

语义不变,颜色随主题自适应(`LIFECYCLE_THEMES.dark / light`,
`getLifecycle()` 读 `<html data-theme>`;MutationObserver 实时重涂,
每个元素用 `dataset.b1Tier` 记忆自己的档位):

| 档 | 语义 | dark | light |
|---|---|---|---|
| init | 初始常量(被除数、固定数字),**绝不允许高亮成黄色** | 亮白 #F8FAFC | 深板岩 #0F172A |
| focus | 当前工作值/焦点(全场唯一黄) | #F5C542 + 微光 | 黄底色块 + 琥珀字 |
| result | 刚产出(绿微光闪烁后即让位) | 纯白 + 绿光 | 深板岩 + 绿光 |
| history | 已产出的重要历史(商、最终结果) | #94A3B8 @0.8 | #64748B @0.75 |
| consumed | 被消耗的过程数据(乘数/减数/旧余数),**禁止删除线** | #475569 @0.4 | #475569 @0.4 |

判定纪律:档位由 `(waitingFor, step, filled, broughtDown)` 纯推导;
"完成"的判定要指向"最后一个结果已填",不要用 step 指针(它在最后一步进行中就会相等,踩过)。

## 三、GSAP 动效语言

- 缓动:入场/位移 `power2.out`;新数字落地 `back.out(1.2)`;终局强调 `elastic.out`;消失 `power2.in`。绝不用 linear。
- 重力:新元素从 y:-20 ~ -26 砸下,配 opacity 0→1。
- 呼吸降噪:计算某一步时,非焦点元素 opacity → 0.4;结束后先恢复 1.0,再随生命周期沉入 consumed。
- 时间轴留白:合并/画线结束必须 `tl.to({}, {duration: 0.25})` 让大脑处理信息。
- 组合拳:`tl.to(..., "-=0.1")` 让动作重叠;画线到 70% 数字才起步。
- 键盘/动画时序:**一道题没算完,键盘绝不收起**(见第五节)。
- `prefers-reduced-motion`:timeScale 加速 + 关闭 CSS 抖动动画。
- ⚠️ **CSS 里绝不写初始 transform**:会被 gsap 解析烘焙成 px 分量,
  yPercent 补间清不掉它(键盘卡屏外的教训)。初始位移一律 `gsap.set`。

## 四、页面场景化与收纳(克制哲学)

共享 Chrome 已抽到 `core/ui/brilliant-chrome.js`(`ensureChromeStyle()`):
`.b1-topbar / .b1-actions / .b1-iconbtn / .b1-sheet / .b1-mask / .b1-hint / .b1-awaiting 聚光灯`。

1. **功能收纳**:题库选择、载入、上传、随机、数字设置 → 全部收进 ⚙ 图标,
   点击弹**底部抽屉**(Bottom Sheet);换题动作完成后自动收起抽屉。
   主界面默认只留:当前算式/竖式 + 下一步指令。
2. **按钮边缘化**:大按钮(重来/下一步)缩成顶栏小图标(↻ / ▶),
   ▶ 在等待填写时自动半透明禁用。
3. **核心聚焦**:C 位只留给当前算式/竖式;提示语弱化
   (次级灰 #64748b、16px、`.b1-hint:not(.ok):not(.error)` 保住语义色)。
4. **排版**:算式超大等宽(38px,Consolas 栈 + tabular-nums),
   算式与标题间距 margin-top 40px,与提示语间 32px。
5. **聚光灯**:等待输入时 `.b1-awaiting` 让顶栏/提示/测验盒退到 opacity .4,
   算式内非焦点元素由呼吸降噪处理。
6. 若新色彩与现有代码冲突,**以现有代码为准**(语义色 ok/error 不可被弱化覆盖)。

## 五、共享虚拟键盘(`core/ui/virtual-keypad.js`)

单例组件,所有模块 `getVirtualKeypad().show({onDigit, onConfirm})` 即用。

**主题契约**(CSS 变量名与 MathLive 虚拟键盘一致,宿主可覆盖):
```css
--keyboard-background: #f8fafc;
--keycap-background: #ffffff;
--keycap-text: #1e293b;
--keyboard-accent-color: #29CC57;
--keycap-height: 52px;      /* 默认 52,宿主可调 */
--keycap-font-size: 22px;
```

**行为契约**(六条,组件已实现,业务侧必须遵守):
1. **只在需要时提供输入**:点算式/进入等待态才 `show()`;业务确认回调里收缓冲。
2. **绝不让原生键盘弹起**:组件用 pointerdown + preventDefault,永不抢 DOM 焦点;
   业务侧移除原生 `<input>`,答案用"答案槽"(span + ?占位 + 闪烁光标 CSS)。
3. **持久性**:show 后常驻;**确认后不收**(下一步还要用);
   答错不收;只有**终局**(整题算完)业务才调 `hide()`,
   键盘滑下后由拇指条/继续按钮接管。
4. **点外自动确认**:键盘以外的按下 = "我输完了"(沿用原失焦提交习惯)。
   空缓冲不触发;arm 发生在 click 之后(同一次 tap 的 pointerdown 早于它,不会误吞)。
5. **页面让位**:show 时组件自动给 body 加等高 padding;
   业务侧对提示语调用 `ensureVisible(fb)` 把它滚到键盘上沿之上
   (scrollIntoView 不知道 fixed 键盘是覆盖层,必须用组件方法)。
6. **物理键盘补充**(桌面):数字/Enter/Backspace 走 window keydown,
   与虚拟键盘写同一个缓冲。

## 六、竖式网格专属规范(m9,二维格)

1. **步骤组渐进展开**:建格时每一步的行组(乘积/减法线/余数/落位格)打标
   `stepCells[idx]` 且 `display:none`(行高塌缩为 0);进行到该步才展开。
   网格高度随计算过程增长(实测 100 → 250 → 400px),提示语不被键盘推走。
2. **落位(Bring Down)**:上一步余数填完 → 下一位被除数在余数行**直接渲染**,
   y:-20 back.out 砸下;源数字原地变灰占位;`M9.broughtDown`(Set)先登记再动画,
   保证刷新绝不重复动画。
3. **工作值语义**:余数行 + 落位格 = 当前工作值(如 58)= focus 黄;
   算出新余数(步骤完成)→ **立刻**褪成 consumed。
4. **列映射纪律**:借位/进位"产生列"与"显示列"差一
   (渲染映射:格 c-i 显示 carry-(i+1))——挂输入槽时必须换算,
   并用回归测试锁死(50−3 的借位槽必须挂 c-0,即左侧数字上方)。
5. **减法线**:建格时 opacity 0,乘积落位后浮现;跨度取乘积列(教科书式)。
6. **档位映射**(÷):商/最终余数 → history;乘积/进位/中间余数 → consumed;
   工作值 → focus;被除数/除数 → init(永不黄)。
   加减乘:结果位 → history,进位 → consumed,常量 → init。

## 七、横向算式专属规范(m1 摘要)

- 弧线漏斗:SVG 三次贝塞尔 C 指令下潜弧,stroke 1.5px 圆帽,
  stroke-dasharray 从左侧数字底部"发芽";弧底中心采样取最低点,
  垂直指示线精准指向新行结果格顶端(源区间布局保证对齐)。
- 源区间布局:`reduceWithSrc`(归并 + 括号折叠时扩展源区间)→
  `computeRowLayout`(新格继承上一行**真实渲染边缘**,严禁按 token 重估)→
  `mergedGlyphShift`(左右操作数不等宽时,字形 relative-left 压回弧底正下方,盒子不动)。
- SVG 不用 viewBox 缩放(面板长高会拉伸旧弧线),用 px 属性 + overflow:visible。
- 键盘持久 + 连续计算:确认 → 弧线合并 → 新行 → 界面待命,键盘原位续输下一。

## 八、渐进式迁移流程(新模块七步)

1. **数学下沉**:把渲染层里的推导搬进 `scoring/mX.js` 导出纯函数 + 测试;
   与已有判卷函数做一致性断言(防双实现漂移)。
2. **令牌接线**:尺寸进 `DIMENSION`/`GRID`,色彩走 `LIFECYCLE_THEMES`,
   动效走 `MOTION`/`EASE`;模块内出现魔法颜色/时长即违规。
3. **建格一次**:把 innerHTML 全量重绘改成 buildOnce + 注册表
   (`data-mXkey`)+ 原地刷新;换题才允许清空。
4. **颜色状态机**:实现 `currentTarget()` 单一入口 + `setTier()`,
   按第六/二节的映射上色;先让颜色对,再动动画。
5. **键盘接入**:挂答案槽 → `keypad.show({onDigit, onConfirm})` →
   缓冲清理(新目标必须清!)→ 点外确认 + 物理键盘 + `ensureVisible(提示语)`。
6. **动画**:按第三节节奏补砸落/合并/褪色;动画 onComplete 才改状态。
7. **收纳**:顶栏图标 + 底部抽屉 + 提示弱化(第四节)。

每步改完立刻验证(测试 + 截图),一次只动一小块。

## 九、防雷清单(今天真实踩过的坑)

| 坑 | 症状 | 规则 |
|---|---|---|
| CSS 写初始 `transform: translateY(105%)` | 元素永远卡在屏外 | 初始位移用 `gsap.set`,CSS 零 transform |
| `grid.meta = { steps, n }` 末尾覆盖 | 步骤组数据丢失,刷新崩溃 | meta 一次性组装,或尾部展开保留 |
| `makeCell` 只创建不挂载 | 网格里只剩线条 | 建格工具返回值必须 appendChild |
| 答案缓冲跨步不清 | 上一格数字串进下一格('4'+'28'→'428') | 挂新目标时强制清缓冲 |
| 旧行可点元素不退役 | 多步题第二点被旧索引吞掉 | 提交时 committed 标记 + 锁定 + 入口校验 |
| 完成判定用 step 指针 | 最后一步进行中误判完成 | 用"最后一个结果已填" |
| `scrollIntoView` 对抗 fixed 键盘 | 提示语仍被遮 | 用键盘组件 `ensureVisible` |
| jsdom 缺 SVG 几何/scrollIntoView | 测试假失败 | 测试文件顶部统一打桩 |
| 卸载后迟到定时器写 DOM | uncaught TypeError | 回调入口判空(`if (!fb) return`) |
| 动态 import 相对路径多写一层 | 模块 500(vite 才暴露) | 核心层引用 app 用 `../app/`,ui 子目录才 `../../app/` |
| 共享单例元素被页面重置扫掉 | 单例失效 | `_ensureAttached()` 自愈重挂 |

## 十、验收标准

1. `pnpm vitest run` 全绿;新模块至少包含:
   纯函数一致性测试、全流程交互冒烟(键盘化)、
   回归锁定(对位/档位/持久性/防重复动画)。
2. 真机(无头 Edge + playwright,420×700 小屏)全流程截图:
   干净主界面 → 抽屉 → 键盘弹出 → 合并/落位中 → 待命(键盘保持)→ 终局(键盘滑下+拇指条),
   每帧对照本文件检查;控制台零错误。
3. 桌面物理键盘可用;移动端全程无原生键盘弹起。
4. 交互过程中任何元素不允许布局位移;动画结束状态 = 档位状态。
